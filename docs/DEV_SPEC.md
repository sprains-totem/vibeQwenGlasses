# vibeQwenGlasses 项目开发规范与客观验证红线

> **核心军规**：
> **走都不会走，严禁说已经会跑。卡在验证阶段就必须就地彻底攻克，严禁跳过错误、严禁伪造就绪状态、严禁虚报进度。**

---

## 一、三条铁律（开发红线）

### 1. 严禁跳过未通过的验证步骤
* **禁止任何“假就绪”**：若底层握手、协议协商、GMA 鉴权未收到硬件端（眼镜）的真实确认帧，**严禁通过超时兜底强推状态机至 `READY`**。
* **就地阻断与排查**：卡在哪个协议环节，状态机必须明确停留在对应的错误/等待状态（如 `AUTH_FAILED`、`HANDSHAKE_TIMEOUT`），并立即就地抓包、逆向、修复该环节，严禁在未通过的半截状态上继续编写或触发下游业务逻辑（如直接调录音）。

### 2. 验证完成的唯一判定标准是客观物理数据
* **鉴权成功的判定标准**：
  - 必须真实收到眼镜回发的 `0x13 0x00`（或 0x15/0x16 流程的最终 Success 帧）；
  - `latest.log` 中必须有明确的物理读取记录（`[IO] 收到 ...`）。
* **录音采集打通的唯一判定标准**：
  - 音频帧计数 **`frames_captured > 0`**（严禁为 0）；
  - 生成的 `.wav` 文件大小必须 **显著大于 44 字节**（必须包含连续 PCM 数据流）；
  - 从真机 pull 出音频文件后，波形检查有正常人声/环境声信号，真机可正常播放；
  - 严禁单凭“向眼镜发送了录音指令”就声称录音已打通。

### 3. 测试与汇报必须如实展示硬指标
* 每次测试汇报，必须包含以下不可造假的硬件指标：
  1. 真实生成的录音文件路径与**精确字节大小**（如 `44B` 必须诚实报 `44B 空文件`，不得隐瞒）；
  2. 捕获帧数 `frames_captured`；
  3. 麦克风峰值分贝 `last_db`；
  4. 眼镜返回报文的原始 Hex 日志。

## 二、状态机与超时规范

1. **协议状态机严格对应物理握手**：
   ```
   DISCONNECTED -> CONNECTING (GATT/L2CAP) -> L2CAP_CONNECTED 
                -> NEGOTIATING_GCSP -> AUTHENTICATING_GMA 
                -> [仅当收到 0x13 时] -> READY
                -> [若未收到] -> AUTH_FAILED (严禁跳入 READY)
   ```
2. **严禁无意义的“宽容超时”**：
   - 超时应当作为**错误判定**（触发重试或报错），绝不能作为“跳过鉴权直接就绪”的通行证。
